# M5.1 SidecarClient (C++)

- status: done
- depends: M4.5, M1.1
- files: `app/src/agent/SidecarClient.{h,cpp}`, `app/src/agent/Protocol.{h,cpp}`, `tests/test_protocol_cpp.cpp`
- goal: The app can start the sidecar, send messages, and receive typed events on the UI thread.
- spec:
  1. `Protocol.{h,cpp}`: C++ structs for each message in `sidecar/PROTOCOL.md`, with `toJson`/`fromJson` using nlohmann::json.
  2. Locate the sidecar:
     - env var `READER_SIDECAR_CMD` (a full command line, for dev: `sidecar/.venv/bin/reader-sidecar`)
     - otherwise a `reader-sidecar` executable next to the app binary (M8 packaging)
     - on macOS, `Contents/Resources/reader-sidecar`
  3. Spawn with `wxExecute(cmd, wxEXEC_ASYNC | wxEXEC_HIDE_CONSOLE, process, &env)` with `wxProcess::Redirect()`. The env comes from `Settings` (M7.2).
  4. Read stdout on a `std::thread` until EOF, splitting on `\n`. Parse each line and post a `wxThreadEvent` holding the parsed message. Drain stderr to a log file in `wxStandardPaths::GetUserDataDir()/logs/sidecar.log`.
  5. `send(const Inbound&)` writes one line to stdin. Sends are UI-thread only.
  6. Wait for `ready` (10 s timeout) before treating the sidecar as up. Queue sends until then.
  7. On unexpected exit, emit `EVT_SIDECAR_DOWN`. Restart with backoff (1 s, 2 s, 4 s, max 30 s). After restart, the app re-sends `open_project`.
  8. `shutdown()`: close stdin, wait 3 s, then kill. Call it from `MainFrame` close.

- notes:
  - Env seam: `sidecarEnvironment()` in `SidecarClient.cpp` passes the app environment through. M7.2 replaces its body with the Settings-built environment.
  - Events: `EVT_SIDECAR_READY` (version in `GetString()`), `EVT_SIDECAR_MESSAGE` (`GetPayload<protocol::Outbound>()`), `EVT_SIDECAR_DOWN` (reason in `GetString()`). They are delivered synchronously to the sink on the UI thread.
  - Restart: `SidecarClient` re-sends the last `open_project` itself before any queued line. Queued lines are dropped on DOWN because they target the old process's chats. Open chats do not survive a restart, so M5.2/M6.4 must handle `EVT_SIDECAR_DOWN` (mark chats closed, `resume_chat` after the next ready).
  - Backoff doubles 1, 2, 4 ... 30 s and resets to 1 s when the previous run stayed ready for 30 s or more.
  - Ready timeout (10 s) kills the process with SIGKILL, and the exit takes the normal restart path.
  - Shutdown: close stdin, wait up to 3 s for stdout EOF, then SIGTERM, then SIGKILL after 1 more second. The sidecar's SIGTERM handler closes its CLI processes, which a bare SIGKILL would orphan.
  - The log is truncated at each app start. Lines written by the app are prefixed `[app]`. On Linux, wx puts it at `~/.agentic-reader/logs/sidecar.log`.
  - A reader thread that never reaches EOF (a grandchild still holding stderr) is detached and its `wxProcess` is leaked rather than freed under the thread.
  - SIGPIPE is ignored so a write to a dead sidecar fails instead of killing the app.
  - `test_sidecar_client` is not built on Windows because its fake sidecar is a shell script.
  - human check: on Windows and macOS packaged builds (M8), confirm the app finds `reader-sidecar` next to the binary or in `Contents/Resources`, and that closing the window leaves no sidecar process.
