# M5.3 Reader context wiring and "Ask about selection"

- status: todo
- depends: M5.2, M3.2
- files: `app/src/chat/ChatPanel.cpp`, `app/src/chat/ContextChip.{h,cpp}`, `app/src/pdf/PdfView.cpp`, `app/src/MainFrame.cpp`
- goal: Claude always knows the file, page and selection without the user typing them.
- spec:
  1. On send, `MainFrame` asks `PdfView` for `filePath()`, `currentPage()`, `pageCount()`, and `selection()`, and fills `prompt.context`.
  2. A context chip above the input shows "attention.pdf · p. 12 · 214 chars selected". An × on the chip excludes the selection from the next prompt only.
  3. "Ask about selection": PDF context menu entry plus Ctrl+Shift+A. It focuses the chat input and pre-fills `> ` quoted selection text (first 300 chars) followed by a blank line. The full selection still travels in `context`.
  4. When no PDF is open, send no context.
- done when:
  - [ ] Manual: select a paragraph on page 3, ask "what does this mean?". The reply addresses that paragraph and cites p. 3.
  - [ ] Debug check: sidecar log at `DEBUG` shows the `<reader_context>` block with the right values.
- verify: manual run with `READER_SIDECAR_LOG=DEBUG`.

- notes:
  - carried: (M4.4 review) `context.py` prints a relative `file` unchanged. Send absolute paths or forward-slash relative paths, so Windows backslashes do not reach the prompt.
  - carried: (M3.2 review) `Selection::text` skips pages whose text is not loaded yet, so a long drag-scroll can give SelectionInfo text with pages missing and no sign of it. Before sending a selection to the chat, load missing pages (e.g. from the document on the UI thread, or request them) or warn.
  - carried: (M3.2) PdfView::setContextMenuHook(std::function<void(wxMenu&)>) runs before the synchronous PopupMenu; append "Ask about selection" there and Bind on the menu.
