# M6.2 ProjectPanel and opening projects

- status: done
- depends: M6.1, M2.5, M5.1
- files: `app/src/project/ProjectPanel.{h,cpp}`, `app/src/MainFrame.cpp`
- goal: Users open a folder as a project and browse its PDFs.
- spec:
  1. File > Open Project (Ctrl+Shift+O) uses `wxDirDialog`. Add recent projects to the File menu.
  2. `ProjectPanel`: a `wxTreeCtrl` of folders and PDFs. Activating a PDF opens it in `PdfView`.
  3. Refresh with `wxFileSystemWatcher` on add, remove and rename. Debounce 300 ms.
  4. Opening a project sends `open_project {path}` to the sidecar.
  5. Opening a single PDF outside any project opens its parent folder as an unsaved project: no `.reader/` is created and chats are not persisted. The panel header says "Unsaved project" with a "Save as project" button that creates `.reader/`.
  6. On app start, reopen the last project and its `open_file`.
- done when:
  - [x] Manual: open a folder, see PDFs, open one. Add a PDF in a file manager and it appears. Restart and the same project and file come back.
- verify: manual run.

- notes:
  - carried: (M2.5 review) PDF drops are accepted only on the PDF pane (PdfView.cpp:57), not the whole window as M2.5 spec 2 says. When the project panel replaces the left pane, decide whether drops onto it open the file or add it to the project, and keep the PDF pane drop working.
  - carried: (M2.5) Opening a PDF from the same folder keeps the current chat; a different folder sends open_project and a new chat (MainFrame). Replace this with the real project model.
  - Drops (carried note 1): a file dropped on the project panel opens it exactly like a drop on the PDF pane (which still works); it does not copy the file into the project. A folder dropped on either pane opens it as a project, like File > Open Project (creates `.reader/`).
  - Project model (carried note 2): `projectFolderFor()` (project/ProjectTree.h) picks the folder. A PDF anywhere under the open project keeps it and its chat; otherwise the nearest folder with `.reader/` opens, else the PDF's folder as an unsaved project. Each project switch sends `open_project` and starts a new chat (`ChatPanel::openProject`). MainFrame keeps `m_projectRoot` plus `m_project`, which is null for an unsaved project, so nothing is written for it. M6.4 should persist chats only through `m_project` and start persisting at "Save as project" (the running chat continues there).
  - Open Project, Recent Projects and a dropped folder create `.reader/` at once. Only saved projects enter Recent Projects (wxConfig `/RecentProjects/`). `/Session/LastProject` holds the last project, saved or unsaved. At start without a command-line file the app reopens it with its `open_file`; for an unsaved one it reopens the most recent file if it lives there.
  - `open_file` is written when a file opens in a saved project, when leaving it, and on close. Save failures show a message box.
  - The watcher (created on the first `setProject`, which runs from `CallAfter` or later, so the event loop is up) watches the root and every non-hidden subfolder with one `Add` each, re-done after every refresh so new folders are seen. `.reader/` is hidden, so project.json writes do not refresh the tree. Refresh is a restarted 300 ms one-shot timer. Very large trees use one inotify watch per folder.
  - Opening a project whose `open_file` is missing or fails to open (Open Project, Recent Projects, a dropped folder, start) empties the view with `PdfView::closeDocument()` (stops and joins the render thread, bumps the generation so queued results are dropped, clears the page cache and TextLayer, resets layout and scroll). The status bar file field goes back to "Ready" and the page total to "/ 0".

  - human check: quit and restart; the same project and file come back.
