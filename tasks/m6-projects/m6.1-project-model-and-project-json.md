# M6.1 Project model and project.json

- status: done
- depends: M2.1
- files: `app/src/project/Project.{h,cpp}`, `tests/test_project.cpp`
- goal: Load and save the project folder format from the plan.
- spec:
  1. `Project::open(path)`: the folder must exist. Create `.reader/` if missing.
  2. `pdfs()`: recursive scan for `*.pdf` (case-insensitive), skipping `.reader/` and hidden folders, sorted by relative path.
  3. `project.json` schema, version 1:
     ```json
     {"version":1,"open_file":"rel/path.pdf",
      "files":{"rel/path.pdf":{"last_page":11,"zoom":"fit-width"}},
      "chats":[{"id":"uuid","title":"...","session_id":"...|null","created":"ISO8601","updated":"ISO8601"}]}
     ```
  4. Keep transcripts in `.reader/chats/<chat_id>.jsonl`, one line per message `{role, text, ts, cost_usd?}`. The SDK session store does not return history to the app, so the app keeps its own copy.
  5. All writes are atomic: write `*.tmp`, then rename.
  6. Unknown fields are preserved on save. A newer `version` opens read-only with a warning.
  7. A corrupt `project.json` is renamed to `project.json.bak-<timestamp>` and replaced with an empty one, plus a warning.
- done when:
  - [x] Tests: scan filtering and order, round trip, unknown field kept, corrupt-file recovery, atomic write leaves no `.tmp` behind.
- verify: `ctest -R project`
- evidence: commit 8eb9f1d. Full `ctest`: 5/5 passed. `ctest -R project`: 2/2 passed (`project` 12 cases, 194 assertions; `project_transcript` 4 cases, 41 assertions).
- notes:
  - Spec item 4 is implemented here as `Project::appendMessage(chatId, ChatMessage, error)` and `Project::transcript(chatId)`, tested in `tests/test_project_transcript.cpp`. Each append copies the transcript to `.tmp`, appends, and renames, so it stays atomic at O(size) per message. Chat ids must match `[A-Za-z0-9_-]+`. Unparsable lines are skipped on read. M6.4 wires it to the chat pane.
  - Appends and `save()` are refused on a read-only project.
  - Known fields of the wrong type (`files` not an object, `chats` not an array, a chat without a string `id`, and similar) count as corrupt and go through backup recovery. A missing `version` is read as 1.
  - `open_file` is written as `null` when empty. Unknown fields inside a chat entry are kept when the chat `id` still exists after `setChats()`.
  - If project.json cannot be read, or a corrupt one cannot be renamed aside, the project opens read-only with a warning.
  - Relative paths use `generic_string()`. Non-ASCII names on Windows may need `generic_u8string()` later.
