# M9.1 Agent chat keyboard shortcuts

- status: todo
- depends: M6.4, M7.3
- files: `app/src/chat/ChatPanel.{h,cpp}`, `app/src/MainFrame.{h,cpp}`, `tests/acceptance/m9.1.steps`
- goal: Drive the agent chat from the keyboard without reaching for the mouse.
- spec:
  1. A "Chat" menu sits between Project and Help. Items, in order: New Chat (Ctrl+N), Focus Chat Input (Ctrl+L), a separator, then Stop Reply. "Ask about selection" stays in Edit.
  2. Ctrl+N is the New chat button: it calls `ChatPanel::newChat()`. The menu item is disabled (greyed) while a reply runs, matching the button.
  3. Ctrl+L focuses the chat input, like clicking it. It does nothing while the first-run or "API key rejected" banner is shown, when the input is hidden.
  4. Esc is the Stop button: it interrupts the running reply (`ChatPanel::stop()`). It fires only while a reply runs and no modal dialog is open; otherwise Esc is left to whatever has focus. A modal permission dialog keeps Esc for Deny. The Stop Reply menu item is enabled only while a reply runs.
  5. All four shortcuts work while focus is anywhere in the main window, the chat input included. They must not be swallowed by the input (a GTK text view takes some keys for itself): use frame-level menu accelerators, plus a frame `wxEVT_CHAR_HOOK` for Esc and any key a text control would otherwise consume.
  6. Nothing else changes. Enter sends and Shift+Enter inserts a newline in the input; Ctrl+Shift+A, Ctrl+F, Ctrl+O, Ctrl+Q and the Send/Stop buttons behave as before. No new key may shadow an existing one.
- done when:
  - [ ] Ctrl+N opens a new chat from anywhere in the main window, and the menu item is greyed while a reply runs.
  - [ ] Ctrl+L moves the caret into the chat input (typing lands there), from the PDF view, the project panel and the message view.
  - [ ] Esc stops a running reply and does nothing otherwise. With a permission dialog open, Esc still means Deny.
  - [ ] The Chat menu shows New Chat, Focus Chat Input and Stop Reply with their labels.
  - [ ] `ctest` (the whole suite) still passes, and no existing acceptance steps regress.
- verify: `ctest`, then `scripts/shot.sh -o <repo>/.verify/m9.1/impl -s tests/acceptance/m9.1.steps -- ./build/app/agentic-reader`, then a manual run with a real sidecar.

- notes:
  - Key bindings are the proposed defaults and are written here so they can be changed in one place. If Ctrl+L conflicts with something later, Ctrl+K is the fallback for focus input.
  - Esc is not portable as a menu accelerator; wire it through a frame key handler and keep the menu label informational.
  - Out of scope: toggling the chat pane (show/hide) and remappable keys. The former belongs with the layout/fullscreen work, the latter needs settings UI.
  - human check: with a real Claude login, ask a long question, press Esc, the reply stops with the grey "Stopped." line, then Ctrl+N and ask again.
