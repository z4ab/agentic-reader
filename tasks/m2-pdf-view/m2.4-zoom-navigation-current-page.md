# M2.4 Zoom, navigation, current page

- status: done
- depends: M2.3
- files: `app/src/pdf/PdfView.{h,cpp}`, `app/src/pdf/PdfEvents.h`, `app/src/MainFrame.cpp`
- goal: Standard viewer controls and a reliable "current page" for chat context.
- spec:
  1. Zoom modes: custom percent (25%–800%), fit width, fit page. Ctrl+wheel and Ctrl+`+`/`-` step by 10%. Ctrl+0 resets to fit width.
  2. Keep the point under the cursor fixed when zooming with Ctrl+wheel.
  3. Keys: PgUp/PgDn (one viewport), Home/End, Up/Down (scroll 40px), Ctrl+G opens a go-to-page box.
  4. Current page is the page with the most visible area. Emit `EVT_PDF_PAGE_CHANGED` (custom `wxCommandEvent`, int = 0-based page) when it changes.
  5. Toolbar in `MainFrame`: zoom combo, fit width, fit page, page entry `12 / 15`. Status bar shows the file name.
  6. Public getters: `currentPage()`, `pageCount()`, `zoom()`, `filePath()`.
- done when:
  - [x] All keys and controls work on the sample PDF and a large PDF.
  - [x] Page entry and status bar update while scrolling.
  - [x] Zoom toward the cursor keeps the same word under the cursor.

- notes:
  - carried: (M2.3) Call `PdfView::invalidateRenders()` when zoom changes so queued renders at the old scale are dropped.
  - carried: (M2.3 review) PdfView.cpp:111-123: if visible pages plus one above and below exceed the 256 MB cache budget (very high zoom), each `put` evicts a visible page and rendering never settles. Cap the zoom or size the budget to the visible set.
  - Both carried notes are handled: `applyZoom` calls `invalidateRenders()`, and `onPaint` raises the `PageCache` budget to the visible set (new `PageCache::setBudget`), only prefetching neighbours that fit next to it. At 800% the view settles (shots 16 and 17 match).
  - Added `EVT_PDF_ZOOM_CHANGED` (also in `PdfEvents.h`) so the toolbar combo follows Ctrl+wheel and key zoom.
  - PdfView uses the client size from the last size event, not `GetClientSize()`. On wxGTK 3.3, `GetClientSize()` subtracts overlay scrollbars right after one shows or hides, and no size event corrects it. That left the view scrolled 5px sideways after Fit Page from 800%.
