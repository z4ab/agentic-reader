# M2.3 Background rendering and bitmap cache

- status: done
- depends: M2.2
- files: `app/src/pdf/RenderWorker.{h,cpp}`, `app/src/pdf/PageCache.{h,cpp}`, `app/src/pdf/PdfView.cpp`, `tests/test_page_cache.cpp`
- goal: Scrolling stays smooth on a 500-page PDF.
- spec:
  1. `RenderWorker` owns a `std::thread` and its own `PdfDocument` instance opened from the same path. It takes a queue of `(page, scale, generation)` requests.
  2. It renders to `wxImage` and posts a `wxThreadEvent` carrying `(page, scale, generation, wxImage)` to `PdfView`. Never create `wxBitmap` off the UI thread.
  3. When zoom changes or the document changes, bump `generation`, clear the queue, and drop results from older generations.
  4. Request order: visible pages first, then one page above and below.
  5. `PageCache`: LRU keyed by `(page, scale)` with a byte budget (default 256 MB). Pure C++ apart from storing `wxBitmap`. Test eviction with fake sizes.
  6. While a page renders, paint the white page rect only. When the image arrives, convert to `wxBitmap` and `RefreshRect` that page.
  7. Shut down the worker cleanly in the `PdfView` destructor (stop flag, notify, join).
- done when:
  - [x] Cache tests pass.
  - [x] Scrolling a 500+ page PDF never blocks the UI for more than one frame. Measure by holding PgDn.
  - [x] Closing the window while pages render does not crash or hang.
- verify: `ctest -R page_cache`. Manual scroll test with a large PDF. Record its source and page count in `notes`.
- evidence:

- notes:
  - Large PDF: `tests/data/long.pdf`, 520 US Letter pages, generated by `tests/data/make_long_pdf.py`.
  - The worker queue is replaced on every paint with the current visible pages plus one above and below, so pages scrolled past are not rendered. A request equal to the page rendering now is skipped.
  - Cache entries stay across render scale changes because the key includes the scale. They are cleared when a new document opens. `PdfView::invalidateRenders()` bumps the generation and clears the queue; M2.4 should call it on zoom changes.
  - The worker opens the document with an empty password. M2.5 (encrypted PDFs) must pass the password to `RenderWorker`.
  - human check: hold PgDn on long.pdf and a real 500+ page PDF on a desktop and confirm scrolling feels smooth, with blank pages filling in shortly after.
  - human check: on a HiDPI display (scale 2), confirm pages render sharp and the 256 MB budget still holds enough pages for smooth scrolling.
