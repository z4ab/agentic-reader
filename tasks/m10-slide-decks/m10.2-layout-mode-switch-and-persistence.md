# M10.2 Layout mode in PdfView, switching and per-file storage

- status: done
- depends: M10.1, M6.5
- files: `app/src/pdf/PdfView.{h,cpp}`, `app/src/pdf/PdfEvents.h`, `app/src/MainFrame.{h,cpp}`, `app/src/project/Project.{h,cpp}`, `tests/test_project.cpp`, `tests/data/make_slides_pdf.py`, `tests/data/slides-16x9.pdf`, `tests/acceptance/m10.2.steps`
- goal: Slide PDFs open one slide at a time, and the user can switch modes per file.
- spec:
  1. `PdfView::setLayoutMode(LayoutMode)` and `layoutMode()`. On open, `PdfView` uses the layout the caller passes in, else `detectLayout`. The file never shows in the wrong mode, even for one frame.
  2. Default zoom is fit width for Continuous and fit page for SinglePage. Ctrl+0 returns to the current mode's default. Fit modes re-fit on window resize and chat splitter drag.
  3. In SinglePage the current page is the page on screen. `goToPage` shows the target page and keeps the zoom.
  4. View menu radio items "Continuous" and "Single Page", a toolbar toggle, and Ctrl+Shift+L switch modes. Switching keeps the current page and applies the new mode's default zoom. `EVT_PDF_LAYOUT_CHANGED` is sent only for user switches. Ctrl+Shift+L must not shadow an existing key.
  5. `FileState` gains an optional `layout` (`"single"` or `"continuous"`), written to project.json only when the user's choice differs from `detectLayout`. On `EVT_PDF_LAYOUT_CHANGED`, store it or remove the key if the choice matches detection. On open, pass the stored layout before the first layout, then restore zoom and last page.
  6. `tests/data/slides-16x9.pdf` is generated by a checked-in script (like `make_long_pdf.py`), at least 5 pages of 16:9 with distinct text per page.

- notes:
  - Design: DESIGN.md D1-D4, D8, "Zoom and navigation (M2.4)" and "Project file and reading position (M6.1, M6.5)".
  - Interface choices: `PdfView::setDocument(doc, password, std::optional<LayoutMode> layout = nullopt)` takes the stored layout. `PdfView::setLayoutMode(mode)` is the user switch. It keeps the page, applies the mode's default fit zoom and sends `EVT_PDF_LAYOUT_CHANGED` (GetInt is the mode). `detectedLayout()` lets MainFrame store the layout only when it differs.
  - Zoom on open: a fit zoom resets to the layout's default only when the layout differs from the previous document's. A custom zoom is kept, so Continuous-to-Continuous opens are unchanged.
  - Ctrl+Shift+L is caught in the frame's CHAR_HOOK, as Ctrl+Shift+A is, so it works with the chat input focused. The accelerator text is on both View radio items.
  - The toolbar toggle ("Single Page") sits after the page total, so the click points in m2.4 and m10.2 are unchanged.
  - Ctrl+0 in SinglePage fits the page. In Continuous it still fits the width.
  - Pre-existing: a GLib-GObject-CRITICAL `g_object_unref` assertion appears on quit. The baseline build of 1e0f484 shows it too (plain open and Ctrl+Q, no layout switch), so this task did not cause it.
  - Not done here, by spec: keys and wheel in SinglePage (M10.3). Find next/prev to a match on another page does not flip the page yet, since `pageToView` is empty for a non-shown page (M10.4). Selection is not cleared or moved on a layout switch (M10.4).
  - Lock: `m6.5.sh` ran before the shared build lock rule, the m2.4 runs, the baseline build and the final build ran under `.verify/build.lock`.
