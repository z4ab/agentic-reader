# M10.3 Single Page navigation: keys, wheel and toolbar

- status: todo
- depends: M10.2
- files: `app/src/pdf/PdfView.{h,cpp}`, `app/src/pdf/ViewNav.{h,cpp}`, `app/src/MainFrame.{h,cpp}`, `tests/test_pdf_view_nav.cpp`, `tests/acceptance/m10.3.steps`
- goal: Flip slides with the keys, wheel and buttons people expect from a slide viewer.
- spec:
  1. SinglePage keys: Right, PgDn, Space and N go forward. Left, PgUp, Shift+Space and P go back. Home/End go to the first/last page. Ctrl+G works as in Continuous. Up/Down scroll 40px within a page that overflows the viewport and flip at its edge, and flip directly when the page fits.
  2. SinglePage wheel: when the page fits, accumulate `GetWheelRotation()` and flip one page per `GetWheelDelta()`, ignoring wheel events for 150 ms after a flip. When the page overflows, the wheel pans and one more full notch at the edge flips. Going forward shows the new page from its top, going back from its bottom. Ctrl+wheel still zooms.
  3. Put the flip decision (accumulator, lockout, edge test) in a window-free helper in `ViewNav` so it is unit tested.
  4. The toolbar gains Previous and Next page buttons, active in both modes. In Continuous they call `goToPage(current ± 1)`.
  5. Continuous mode keys and wheel behave as before. The chat input and find bar keep their keys (N, P and Space type text there).
- done when:
  - [ ] Unit tests for the flip helper: one notch flips once, a burst inside 150 ms flips once, partial rotation accumulates, overflow pans before flipping, no flip past the first or last page.
  - [ ] Every key in item 1 works in SinglePage (screenshots show the page number change).
  - [ ] Prev/Next buttons work in both modes.
  - [ ] `ctest` passes and existing acceptance steps do not regress.
- verify: `ctest`, then `scripts/shot.sh -o <repo>/.verify/m10.3/impl -s tests/acceptance/m10.3.steps -- ./build/app/agentic-reader tests/data/slides-16x9.pdf`.
