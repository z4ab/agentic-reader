# M10.1 PageLayout single-page mode and layout detection

- status: todo
- depends: M2.4
- files: `app/src/pdf/PageLayout.{h,cpp}`, `app/src/pdf/LayoutDetect.{h,cpp}`, `app/src/pdf/ViewNav.{h,cpp}`, `tests/test_page_layout.cpp`, `tests/test_layout_detect.cpp`
- goal: Window-free layout math for a one-page-at-a-time mode, and detection of slide decks from page shape.
- spec:
  1. `enum class LayoutMode { Continuous, SinglePage }`. `PageLayout::compute` gains a `LayoutMode` and a shown page (used only in SinglePage) and a viewport height. Continuous output is unchanged.
  2. SinglePage: only the shown page has a rect, centred on both axes when smaller than the viewport. Other pages get `{0, 0, 0, 0}`. Total size is the larger of the viewport and the page plus `kGap` on each side.
  3. `pageAt`, `visiblePages`, `pageToView` and `viewToPage` return only the shown page in SinglePage. `viewToPage` returns page -1 outside it.
  4. `detectLayout(const std::vector<PageSizePts>&) -> LayoutMode` is a pure function over the sizes from `PdfDocument::pageSizePts` (after rotation). It checks the first 20 pages. More than half with width/height >= 1.2 gives SinglePage, otherwise (or no pages) Continuous.
  5. `fitWidthZoom` and `fitPageZoom` in `ViewNav` work for both a portrait page and a 16:9 page. No change if they already do.
- done when:
  - [ ] `PageLayout` tests cover both modes: gaps, centring on both axes in SinglePage, `pageAt`, `visiblePages`, and the `pageToView`/`viewToPage` round trip in SinglePage.
  - [ ] `detectLayout` tests: Continuous for portrait Letter and A4, SinglePage for 16:9 and 4:3, Continuous for a portrait document with one landscape page, Continuous for an empty list.
  - [ ] `ctest` (the whole suite) passes. No visible change in the app.
