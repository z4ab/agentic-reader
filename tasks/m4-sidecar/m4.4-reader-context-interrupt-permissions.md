# M4.4 Reader context, interrupt, permissions

- status: done
- depends: M4.3
- files: `sidecar/reader_sidecar/context.py`, `sidecar/reader_sidecar/permissions.py`, `sidecar/reader_sidecar/chats.py`, `sidecar/tests/test_context.py`, `sidecar/tests/test_permissions.py`
- goal: Every prompt carries what the user is looking at. Users can stop replies and approve tools.
- spec:
  1. `build_prefix(context) -> str` produces the `<reader_context>` block from the plan. Paths are relative to the project root. Pages are 1-based. The selection is capped at 8,000 chars with "[truncated]" appended. Omit lines whose values are missing. With no context at all, add no block.
  2. `interrupt {chat_id}` calls `client.interrupt()`. The running response ends with its normal `result`, or `error {kind:"interrupted"}` if the SDK raises.
  3. `can_use_tool(tool_name, input, ctx)`:
     - create `req_id` (UUID), store an `asyncio.Future`, send `permission_request {req_id, chat_id, tool, input}`
     - await the future with a 5-minute timeout. A timeout counts as deny.
     - `permission_reply {req_id, allow}` resolves the future
     - return `PermissionResultAllow()` or `PermissionResultDeny(message="User denied")`
  4. Deny all pending requests when a chat closes.
- done when:
  - [x] Tests: prefix formatting (full context, missing fields, truncation), permission allow, deny, timeout (use a short test timeout), interrupt on the fake client.
- verify: pytest
- evidence: b730efa plus review 1 fix. `sidecar/.venv/bin/pytest` 179 passed (test_context.py and test_permissions.py 39 passed). Tester files unchanged since b0caa95.
- notes:
  - Interrupt on an idle chat does nothing. On an unknown chat it sends `error {kind:"unknown_chat"}`. An interrupted reply that ends without a result also sends `interrupted`. Implementer tests in `sidecar/tests/test_interrupt_edges.py`.
  - A reply to an unknown or expired `req_id` is logged and ignored. The app gets no message when a request times out or its chat closes, so M5 should close a stale permission dialog itself (for example when the chat's `result` or `error` arrives).
  - `permission_request` sends the tool input unchanged, so the user sees everything they approve.
  - An interrupt while a chat's client is still connecting skips client.interrupt(). The reply sends `error {kind:"interrupted"}` after connect and never sends its query (review 1).
  - The M4.3 placeholder tests in `test_chat_edges.py` were removed with the placeholder. `PROTOCOL.md` now describes interrupt, the 5-minute timeout, and that only `allow: true` allows.
  - carried: (M4.1 review) `protocol.decode` does not check value types, so `"allow": "no"` is a truthy string. Treat a permission reply as allow only when `allow is True`.
  - carried: (M4.3) `can_use_tool` in `chats.py` is a placeholder that allows Read, Glob and Grep and denies everything else. Replace it with the permission flow.
