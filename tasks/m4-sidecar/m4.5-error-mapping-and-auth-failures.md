# M4.5 Error mapping and auth failures

- status: done
- depends: M4.4
- files: `sidecar/reader_sidecar/errors.py`, `sidecar/reader_sidecar/chats.py`, `sidecar/tests/test_errors.py`
- goal: The app gets one clear error kind per failure it must handle differently.
- spec:
  1. Map exceptions to `error.kind`:
     - `CLINotFoundError` → `cli_missing`
     - `CLIConnectionError` and `ProcessError` → `process`
     - `ResultError` → `result`, with the message carrying `terminal_reason`
     - an auth failure → `auth`. Detect it from the SDK's error text or result subtype. Record the exact signal you found in `notes`.
     - a rate limit (`RateLimitEvent` or a 429 text) → `rate_limit`
     - anything else → `internal`
  2. Never include environment variables or the API key in error messages.
  3. A crashed chat is removed from the registry so `resume_chat` can recreate it.
- done when:
  - [x] Tests for each mapping using the fake client raising each exception.
  - [x] Live check: an invalid key yields `error {kind:"auth"}`.
- verify: pytest plus `scripts/live_smoke.py` with `ANTHROPIC_API_KEY=bad`.
- evidence:

- notes:
  - Auth signal observed live (bundled CLI, SDK 0.2.163, bad key): no exception. The turn yields `AssistantMessage(error="authentication_failed", content=[TextBlock("Invalid API key · Fix external API key")])`, then `ResultMessage(subtype="success", is_error=True, api_error_status=401, terminal_reason="api_error", result="Invalid API key · Fix external API key")`. The CLI process stays up. `errors.py` treats any of `AssistantMessage.error == "authentication_failed"`, `api_error_status == 401`, or the text `Invalid API key`, `authentication_error`, `API Error: 401` as auth.
  - An error result inside a turn (`is_error=True`) ends the reply with one `error` and no `result`, except after an interrupt, where a plain `result`-kind failure still sends `result` as M4.4 did. The chat stays open because its CLI is still running. Only exceptions of `CLIConnectionError` or `ProcessError` remove the chat.
  - Error messages are fixed sentences. `result` adds `terminal_reason` and `subtype` only when they match `[a-z][a-z0-9_]*`. Reply failures are logged to stderr with secret-looking env values (`ANTHROPIC_*`, names with KEY, TOKEN, SECRET, PASSWORD) replaced by `[redacted]`.
  - `scripts/clean-env.sh` keeps the vars named in `CLEAN_ENV_KEEP`. `live_smoke.py` sets it from `--keep-env NAME` and adds `--expect-error KIND`.
  - Nested tool input truncation (optional carried note) is not done.
