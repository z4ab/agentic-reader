# M4.5 Error mapping and auth failures

- status: todo
- depends: M4.4
- files: `sidecar/reader_sidecar/errors.py`, `sidecar/reader_sidecar/chats.py`, `sidecar/tests/test_errors.py`
- goal: The app gets one clear error kind per failure it must handle differently.
- spec:
  1. Map exceptions to `error.kind`:
     - `CLINotFoundError` → `cli_missing`
     - `CLIConnectionError` and `ProcessError` → `process`
     - `ResultError` → `result`, with the message carrying `terminal_reason`
     - an auth failure → `auth`. Detect it from the SDK's error text or result subtype. Record the exact signal you found in `notes`.
     - a rate limit (`RateLimitEvent` or a 429 text) → `rate_limit`
     - anything else → `internal`
  2. Never include environment variables or the API key in error messages.
  3. A crashed chat is removed from the registry so `resume_chat` can recreate it.
- done when:
  - [ ] Tests for each mapping using the fake client raising each exception.
  - [ ] Live check: an invalid key yields `error {kind:"auth"}`.
- verify: pytest plus `scripts/live_smoke.py` with `ANTHROPIC_API_KEY=bad`.
