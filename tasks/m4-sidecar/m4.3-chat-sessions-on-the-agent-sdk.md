# M4.3 Chat sessions on the Agent SDK

- status: done
- depends: M4.2
- files: `sidecar/reader_sidecar/chats.py`, `sidecar/reader_sidecar/main.py`, `sidecar/tests/test_chats.py`, `sidecar/tests/fakes.py`
- goal: Real conversations with streaming output, one `ClaudeSDKClient` per chat.
- spec:
  1. `open_project {path}` stores the project root. It closes existing chats if the root changes.
  2. `new_chat {chat_id}` / `resume_chat {chat_id, session_id}` create a `ClaudeSDKClient` with `ClaudeAgentOptions`:
     - `cwd=project_root`
     - `setting_sources=["project"]` (loads the project's `CLAUDE.md`, ignores the user's global settings)
     - `system_prompt={"type":"preset","preset":"claude_code","append": READER_PROMPT}`. Check the exact preset shape against the SDK reference for the pinned version.
     - `include_partial_messages=True`
     - `allowed_tools=["Read","Glob","Grep"]`
     - `can_use_tool=` the handler from M4.4
     - `resume=session_id` when resuming
     - `model` from the env var `READER_MODEL` if set
  3. `READER_PROMPT` lives in `reader_sidecar/prompts.py`. It tells Claude it is inside a PDF reader, that `<reader_context>` describes what the user sees, that it must cite pages as "p. N", and that it should read PDFs with the Read tool's page ranges instead of whole files.
  4. `prompt {chat_id, text, context}`: build the message with `context.build_prefix` (M4.4), call `client.query`, and iterate `client.receive_response()` in a task:
     - `StreamEvent` text deltas → `text_delta`
     - `AssistantMessage` `ToolUseBlock` → `tool_use {name, input}` (truncate input values over 500 chars)
     - `ResultMessage` → `result {session_id, usage, cost_usd}` (`total_cost_usd`)
  5. Accept only one prompt per chat at a time. A second prompt while busy gets `error {kind:"busy"}`.
  6. Create clients through a `ClientFactory` so tests inject a fake that yields scripted messages.

- notes:
  - The live check used the local `~/.claude` login through `scripts/clean-env.sh`, as `tasks/VERIFY.md` requires, not `ANTHROPIC_API_KEY`. `tests/data/sample.pdf` does not exist until M1.2, so the check used a 2-page PDF made with pdflatex in a scratch folder. `live_smoke.py` takes the project folder as its argument.
  - SDK 0.2.164 defines `SystemPromptPreset` as a TypedDict: `type: "preset"`, `preset: "claude_code"`, and optional `append: str`, `exclude_dynamic_sections: bool`, `snapshot: bool`. The spec's shape matches. The transport passes `append` as `--append-system-prompt`. An omitted `snapshot` acts as true: a resumed session keeps the system prompt recorded on its first request, so later `READER_PROMPT` edits do not reach resumed chats until compaction.
  - `can_use_tool` is the placeholder `chats.deny_unlisted_tools`. It allows Read, Glob and Grep and denies every other tool, so nothing writes until M4.4 replaces it with the permission flow.
  - `prompt` sends the text unchanged. M4.4 adds `context.build_prefix`.
  - `new_chat` or `resume_chat` with no open project answers `error {kind:"no_project"}` and never calls the factory. `tests/test_run.py` (M4.2) sent `new_chat` to the real sidecar and expected only `ready`. It now expects `ready` and the `no_project` error.
  - Error kinds added: `busy`, `no_project`, `chat_exists` (`new_chat` or `resume_chat` for an open chat_id), `unknown_chat` (prompt to a chat that is not open), and `internal` for a failed reply or a reply that ends without a result. The `internal` message names only the exception type. `PROTOCOL.md` lists no kinds. Listing them there after M4.5 would help M5.1.
  - The client connects at the first prompt, inside the reply task. `new_chat` does not block the stdin loop, and an unused chat never starts the CLI.
  - `open_project` compares and stores `Path(path).resolve()`, so another spelling of the same folder keeps the chats.
  - `Router.close()` does all cleanup: it cancels running replies and disconnects every client concurrently. One failed disconnect is logged and does not stop the others. With a real connected client, `close()` running inside a cancelled task (the SIGTERM path) reaped the CLI in 0.81 s. No bundled CLI process remained after the live run.
  - The SDK writes a `CanUseToolShadowedWarning` to stderr once per process because Read, Glob and Grep are in `allowed_tools`. This is intended.
  - Out of scope: with the local login the CLI loads the account's claude.ai MCP connectors even with `setting_sources=["project"]`. The live reply ended with "The Gmail and Google Drive connectors can't be used until you authorize them in your claude.ai connector settings." Candidates: `strict_mcp_config=True` in the options, or `ENABLE_CLAUDEAI_MCP_SERVERS=false` in the dev-login env (M7.2).
  - The live check cost $0.14 on the default model, mostly first-request cache creation.
