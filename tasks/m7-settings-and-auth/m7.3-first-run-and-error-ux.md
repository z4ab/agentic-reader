# M7.3 First run and error UX

- status: todo
- depends: M7.2, M5.2
- files: `app/src/chat/ChatPanel.cpp`, `app/src/chat/SetupBanner.{h,cpp}`
- goal: A new user reaches a working chat without reading docs.
- spec:
  1. If there is no key and dev mode is off, the chat pane shows a banner instead of the input: "Add your Anthropic API key to start", with an "Open Settings" button and a link to `https://console.anthropic.com/settings/keys`.
  2. Error kind actions:
     - `auth` → banner "API key rejected" + Open Settings
     - `rate_limit` → inline notice with a retry button
     - `cli_missing` → "Installation is incomplete, reinstall the app"
     - `process` → "Agent stopped, restarting…" (SidecarClient restarts it)
     - `busy` → ignore (cannot happen from the UI)
     - others → inline message
- done when:
  - [ ] Manual: each state reproduced. For `cli_missing`, point `READER_SIDECAR_CMD` at a sidecar venv where the bundled CLI is removed. Note how in `evidence`.
- verify: manual run.

- notes:
  - carried: (M4.5 review) A rejected RateLimitEvent followed by a non-error ResultMessage sends `result` and no `error`, so the app may not show a rate-limit message.
  - carried: (M4.5 review) A crash exception after an interrupt sends `interrupted` and keeps the dead chat until the next prompt fails with `process`.
  - carried: (M7.1 review) KeyTester::stop() (KeyTester.cpp:380) calls SidecarClient::shutdown() on the UI thread, so Cancel, OK or a re-test during a running Test key can freeze the UI for 3 s or more. Move the shutdown off the UI thread.
  - carried: (M7.1 review) When a wxSecretStore save or delete fails, wx logs its own wxLogError, so the user can see two error boxes. Suppress it with wxLogNull around the call or drop the app's own box.
