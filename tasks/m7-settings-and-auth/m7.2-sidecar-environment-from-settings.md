# M7.2 Sidecar environment from settings

- status: done
- depends: M7.1
- files: `app/src/agent/SidecarClient.cpp`, `app/src/settings/Settings.cpp`
- goal: The sidecar runs with the right credentials and restarts when they change.
- spec:
  1. Build the env from the current process env and remove `ANTHROPIC_API_KEY`, `CLAUDE_CODE_OAUTH_TOKEN`, and `ANTHROPIC_AUTH_TOKEN` so a stray shell variable cannot override settings.
  2. Dev toggle off: set `ANTHROPIC_API_KEY` from the secret store.
  3. Dev toggle on: set no key, so the bundled CLI uses the user's own `~/.claude` login.
  4. Set `READER_MODEL` when a model is configured.
  5. Saving settings restarts the sidecar. Running replies are interrupted, and the chat shows "Settings changed, sidecar restarted".
- done when:
  - [ ] Manual: a valid key works. Switching to dev mode works with a logged-in local Claude Code. Switching to a bad key shows an auth error.

  - Design: `buildSidecarEnv()` (Settings.h) is pure. `Settings::sidecarEnv()` applies it to the current settings and adds `ENABLE_CLAUDEAI_MCP_SERVERS=false`. MainFrame hands it to `SidecarClient::setEnvironmentSource()`, which calls it at every spawn (start, crash restart, `restart()`), so the key store is opened and read only then, and never with the local login (the system key store now opens lazily). `setEnvironment()` changes still apply on top, so KeyTester is unchanged.
  - MCP connectors: `ENABLE_CLAUDEAI_MCP_SERVERS=false` is set in both modes as the default pending the user's decision. The alternative is `strict_mcp_config=True` in `ClaudeAgentOptions` (sidecar/reader_sidecar/chats.py), which ignores every MCP config the CLI would load, not only the claude.ai connectors.
  - Logging: `SidecarClient` logs the sidecar command line with credentials redacted (values of the three credential variables from the app env and from `setEnvironment()`, any `sk-ant-...` token, and any `NAME=value` whose name holds KEY, TOKEN or SECRET). `wxExecute` runs under `wxLogNull`, since its errors can quote the command line. No env value is logged.
  - Every OK in Preferences restarts the sidecar, even with nothing changed (spec 5 says "saving"). The restart blocks the UI up to 3 s while the old sidecar exits (shutdown() path); the real sidecar exits at once on stdin EOF. A running reply is sent `interrupt` and ends with "Stopped.", then the chat resumes its session in the new sidecar.
  - The tester's acceptance steps predate M5.2, so the restart message is shown in both the chat pane (spec 5) and the status bar (steps). The status bar switches to "Assistant ready" once the new sidecar is up.
