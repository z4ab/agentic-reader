# M3.3 Find bar

- status: done
- depends: M3.2
- files: `app/src/pdf/FindBar.{h,cpp}`, `app/src/pdf/SearchWorker.{h,cpp}`, `app/src/pdf/PdfView.cpp`, `app/src/MainFrame.cpp`
- goal: Search the document with highlighted results.
- spec:
  1. Ctrl+F shows a bar above the view: text field, prev/next buttons, a "Match case" checkbox, a result count, and a close button. Esc closes it.
  2. Search runs on a worker thread with its own `PdfDocument`. It calls `page::search` in a loop per page (`search_next_result`) and streams results per page back to the UI. A new query cancels the running search.
  3. Highlight all matches on visible pages in yellow and the current match in orange.
  4. Enter or next goes to the next match and scrolls it into view. Shift+Enter or prev goes back. Wrap around at the ends.
  5. Show the count as "3 of 41" while searching continues.
- done when:
  - [x] Searching a common word in a 500-page PDF shows the first result in under 300 ms and does not freeze the UI.
  - [x] Counts match Papers on the same PDF for three test words.
- verify: manual. Record the three words and both counts in `evidence`.

- notes: Matching is poppler's page::search (substrings, across spaces within a line, case-insensitive unless Match case). Each match re-reads the page text, so words with many matches per page count slowly (all 13000 "fox" take about 13 s in the app, about 27 s for a bare page::search loop), but the first result and the UI are unaffected. The search runs while typing (100 ms debounce); a new query makes the first match in document order current and scrolls to it. Opening or closing a document hides the bar, cancels the search and clears highlights. Steps file note: in 05-scrolled-while-searching page 1's last lines are just above the pane (the bar takes about 42 px), the scroll itself is the expected 600 px. human check: open the same real PDF in Papers and in Agentic Reader, search three words and compare the counts. human check: on a large real PDF, type a common word and scroll, step with Enter/Shift+Enter and toggle Match case while the search runs; the UI should stay smooth.
  - follow-up (M3.3 review): counting many matches per page is slow because the spec requires page::search; matching on text_list ourselves would change poppler's semantics (matches across words, case folding). Revisit only if users notice.
  - follow-up (M3.3 review): a SearchWorker opens a second PdfDocument for every file even if find is never used; closing a very large file while that open runs blocks the UI. Open it on the first search instead.
