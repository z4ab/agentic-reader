# M3.2 Text selection and copy

- status: done
- depends: M3.1
- files: `app/src/pdf/Selection.{h,cpp}`, `app/src/pdf/PdfView.{h,cpp}`, `tests/test_selection.cpp`
- goal: Users select text with the mouse and the app can read the selection for chat.
- spec:
  1. `Selection` holds start and end as `(page, boxIndex)`. Normalize so start is before end in document order. Support ranges across pages.
  2. Mouse: left drag selects. Double-click selects a word. Triple-click selects the line. Click on empty space clears. The cursor becomes an I-beam over text.
  3. Paint selected boxes with a translucent highlight (system highlight color, 35% alpha) using `wxGraphicsContext`.
  4. Ctrl+C and the context menu "Copy" put the text on `wxTheClipboard`.
  5. Public `selection() -> std::optional<SelectionInfo{std::string text; int firstPage; int lastPage;}>`.
  6. Emit `EVT_PDF_SELECTION_CHANGED`.
  7. Leave a context menu hook so M5.3 can add "Ask about selection".
- done when:
  - [x] Tests cover normalization and cross-page text extraction.
  - [x] Manual: selecting a paragraph and pasting into a text editor gives the same text with sane spacing.
- verify: `ctest -R selection`. Manual copy and paste on a single-column and a two-column PDF.

- notes: Two-column layouts depend on poppler's reading order. Record how well it behaves here.
  - carried: (M3.1 review) `TextLayer::textBetween` adds a newline only when the next baseline is lower, so at a column jump the last word of one column and the first of the next run together. Handle it for copied text (e.g. a newline when the next box starts left of and above the current one).
  - carried: (M3.1 review) A stale-generation render result is dropped with its text, although text does not depend on zoom, so fast zooming re-extracts pages (about 3 ms/page on long.pdf). Keep text from stale results if selection needs it sooner.
  - carried: (M3.1 review) TextLayer.h:30 has an overlong comment line.
  - Poppler reading order (poppler-cpp 24.02 here): on `tests/data/twocol.pdf` (each column its own text object) `text_list()` gives heading, the whole left column, then the right column, so a drag from the first left word to the last right word copies the columns one after the other, as a reader expects. The column jump (`omega.` low, `Bravo` high, no space flag) now breaks the line through `TextLayer::separator`, shared by `textBetween` and `Selection`. Selection follows poppler's order, not the geometry: a drag from the left column into the right column selects the rest of the left column plus the start of the right one. Only the synthetic file was checked; real papers with interleaved text objects may order worse.
  - Done for the carried notes: column-jump newline (also in `textBetween`), text from stale-generation results of the same document is kept (`m_documentGeneration`), overlong comment rewrapped.
  - Triple-click: wxGTK reports the third click as a plain press (one or two), so PdfView treats a press within the double-click time and 4 px of the last double-click as a triple-click.
  - A click without a drag (on text or not) clears the selection. A press beside text anchors to the nearest box, and a drag into the page margin snaps to the line's end. Dragging above or below the pane scrolls on mouse motion only (no timer).
  - The selection clears in `setDocument`. M6.2's `closeDocument()` must also call `clearSelection()` (orchestrator to reconcile at rebase).
  - The clipboard holds the text while the app runs (GTK has no flush on exit).
  - human check: select a paragraph of a single-column PDF and of a two-column paper, Ctrl+C, paste into a text editor (gedit, VS Code): same words, single spaces, one line break per PDF line, no `omega.Bravo` run-together at the column jump.
  - human check: hover over text and over the margin; the cursor is an I-beam only over words (screenshots do not capture the pointer).
