# M3.1 Text layer and coordinate mapping

- status: done
- depends: M2.5
- files: `app/src/pdf/TextLayer.{h,cpp}`, `app/src/pdf/PdfDocument.{h,cpp}`, `tests/test_text_layer.cpp`
- goal: Per-page word boxes in page coordinates, ready for selection and search.
- spec:
  1. `PdfDocument::textBoxes(int page)` wraps `page::text_list()`. Each box has: UTF-8 text, bbox in points, `has_space_after`, and its index in reading order.
  2. Convert `poppler::ustring` to UTF-8 with `to_utf8()`.
  3. `TextLayer` caches boxes per page. Load them lazily on the render worker thread and post them back with the image, since `text_list` is slow on dense pages.
  4. `PageLayout` gains `pageToView(page, rectPts)` and `viewToPage(point) -> (page, pointPts)`, accounting for zoom, HiDPI and page offset.
  5. `TextLayer::boxAt(page, pointPts)` and `TextLayer::textBetween(page, fromIdx, toIdx)`. Join with a space when `has_space_after` is set, and a newline when the next box's baseline is lower by more than half the line height.
- done when:
  - [x] Tests: the round trip `viewToPage(pageToView(r))` returns `r` within 1px. `boxAt` finds a known word in `sample.pdf`. `textBetween` returns the expected sentence.
- verify: `ctest -R text_layer`
- evidence: impl 4478d8e. `ctest -R text_layer` passes (25 cases, 10153 assertions). Full ctest 20/20, sidecar pytest 230 passed. Screenshots of tests/acceptance/m2.4-sample.steps in .verify/m3.1/impl/ match M2.4 (no visible change).
- notes: View coordinates are virtual DIP pixels (the tester's choice): HiDPI enters only the render scale, since PdfView's paint and mouse coordinates are DIP, so `dpiScale` does not change the mapping. Callers subtract the scroll offset (CalcUnscrolledPosition) themselves. `TextBox` lives in PdfDocument.h; `PointPts`, `RectPts`, `PagePoint` and `ViewPoint` (moved from ViewNav.h) in PageLayout.h. PdfView asks for text (`RenderRequest::withText`) when its TextLayer lacks a page and keeps it across zoom changes (page points do not depend on zoom); results from a stale generation are dropped with their text, and the page is asked again on the next paint. `PdfView::textLayer()` is the hook for M3.2. `boxAt` is a linear scan, which is fine for word counts per page; M3.2 may want something faster only if profiling says so. Built against Ubuntu poppler-cpp 24.02 using only `text_list()`, `text_box::{text,bbox,has_space_after}` and `ustring::to_utf8()`, all present in 26.04.
